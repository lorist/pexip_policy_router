Participant Logic
Participant Logic Overview

This rule applies when a participant joins a conference. You can:

  • Match conditions based on call information (identity, device, protocol, etc.)
  • Reject the call with a reason message
  • Allow and optionally modify participant behavior using the response builder
Using Variables in Responses (Click to Expand)

Anywhere text is accepted, you may use Jinja expressions: 

{% verbatim %}{{ remote_alias }} joined from {{ location }}{% endverbatim %}
🧠 Using Jinja in Response Fields

Response values may contain Jinja expressions that dynamically reference call information.

Conditional Response Example {% verbatim %} 
{
              "remote_display_name": "{{ idp_attributes.displayname | default(remote_display_name) | default('Guest User') }}",
              "preauthenticated_role": "{{ 'chair' if call_direction == 'dial_in' else 'guest' }}",
              "rx_presentation_policy": "{{ 'ALLOW' if participant_type == 'api_host' else 'DENY' }}"
            }
{% endverbatim %}
Multi-Line If / Else Example {% verbatim %} 
{% if idp_attributes.organization %}
            Welcome {{ idp_attributes.displayname }} from {{ idp_attributes.organization }}!
            {% elif remote_display_name %}
            Hello {{ remote_display_name }}!
            {% else %}
            Hello guest!
            {% endif %}
{% endverbatim %}
